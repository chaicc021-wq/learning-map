# 架构说明

## 1. 核心数据模型（上游，已核验）

四件套 + 一张图，这是整个项目的骨架：

### topic（微知识点）1,590 条
| 字段 | 含义 | 用途 |
|---|---|---|
| `id` | `mt_xxxx` | 主键 |
| `subject` / `domain` | 学科 / 领域 | 分区、过滤 |
| `name` / `description` | 名称 / 白话描述 | 展示、LLM 上下文 |
| `type` | CONCEPTUAL / PROCEDURAL / REPRESENTATIONAL / LANGUAGE / META | 决定教法（概念要讲、程序要练） |
| `ageRangeStart/End` | 年龄区间 | 纵轴、年级对齐 |
| `centrality` | 中心度 0–1 | **找"地基知识点"**：分数高 = 大量后续依赖它 |
| `evidence[]` | 掌握标准（可判定） | **判"会不会"的判据**，不是分数是行为 |
| `assessmentPrompt` | 检测问题（带 `{{name}}` 占位符） | **直接喂给 LLM 当提问模板** |
| `standards[]` | 课标编号 | 教材映射锚点 |

### dependency（前置边）3,221 条
```json
{"topicId":"mt_A","prerequisiteId":"mt_B","strength":"hard",
 "reason":"Must understand vibrations make sound before finding volume patterns"}
```
- `hard` = 不学 B 就学不了 A；`soft` = 不学 B 会学得吃力
- **每条边带一行原因**——这是它比一般知识图谱值钱的地方：诊断结果能给出人话解释，而不只是"你前置没掌握"
- 整体是 **DAG**（有向无环），所以回溯一定终止，不会打转

## 2. 卡点回溯算法（本项目原创）

```
孩子做错 X
  → 取 X 的 hard 前置（parents[X]）
  → 逐个用 assessmentPrompt 问孩子
  → 哪个答不上，就落到那一层
  → 递归，直到找到"没有更早前置"的地基节点 = 真正的卡点
```

实现（`viz/index.html`）：
- `traceUp(id, depth=4)`：BFS 向上，记录每跳的 `lv` 层级和边原因 → 输出「L1 硬 / L2 软 …」链条
- `traceDown(id, depth=2)`：BFS 向下 → 「修好这个能解锁哪些后续」，给家长/孩子正反馈
- `parents` / `children` 双向邻接表，O(1) 取邻居

**depth 上限 4 是刻意的**：再深对家长没有行动价值，且会把图谱糊成一团。要深挖时改这一个数字。

## 3. 3D 可视化设计

布局是**三层语义编码**，不是随机点云：

| 视觉通道 | 编码的语义 |
|---|---|
| 高度 Y | 年龄（5 岁在底 → 12 岁在顶），带整圈网格线 |
| 方位角 θ | 学科扇区（8 个扇区，地面有色块 + 中文标签 Sprite） |
| 半径 r | 领域环（同领域同环，中心度高的往内收） |
| 节点大小 | `0.22 + centrality×1.6`（地基知识点明显更大） |
| 节点颜色 | 学科色；选中=白，前置链=琥珀，解锁后续=绿 |
| 边 | 硬依赖琥珀 0.30 透明度 / 软依赖蓝 0.16；选中链的边提到 0.9 |

技术要点：
- `InstancedMesh` 一次画 1,590 个球（1,590 次 draw call 变 1 次），过滤靠把 scale 设成 0.0001 而不是重建几何
- 边用两个 `LineSegments`（hard / soft 各一），过滤时整批重建——比逐边控制快
- three.js **本地 vendor**（`viz/vendor/`），无 CDN、无构建、离线可跑 —— 这是给"诊所自建服务器 / 局域网部署"那种场景留的路
- 点击用 `Raycaster.intersectObject(instancedMesh)`，`hit.instanceId` 直接索引回 `topics[i]`
- 中文标签用 `CanvasTexture` + `Sprite`（three 本身没有文字）

## 4. 数据管线

```
上游 data/*.json  →  scripts/gen_viz_data.py  →  viz/data.js  →  viz/index.html
   (1.67MB)             字段缩写 + 去空字段        (1.72MB)        零构建
```

缩写映射（省体积，浏览器端可读）：`s`=subject, `d`=domain, `n`=name, `a0/a1`=age, `c`=centrality, `ev`=evidence, `ap`=assessmentPrompt, `st`=standards, `f/p/h/r`=边四元组。

## 5. 二次开发接口

`window.__VIZ = {camera, controls, byId, D, select, THREE, renderer, scene}` —— 外部脚本可直接调：
- `__VIZ.select('mt_xxx')` 程序化选中任意知识点（自动化测试 / 课件联动入口）
- `__VIZ.byId` 全量 topic 索引
- `__VIZ.D.topics[i].pos` 每个节点的 3D 坐标（做镜头动画、课件飞入）

## 6. 下一步的架构位置（关键判断）

这套东西**不该被当成一个"教育 App"**，它该被当成一个**通用诊断引擎的骨架**：

```
        ┌── 领域知识层（可替换）
        │    学习：微知识点 + 前置依赖 + 掌握标准
        │    健康：异常指标 + 病因链 + 危急阈值
        │
引擎层 ─┼── 回溯算法（同一套 BFS + hard/soft 加权）
        │
        └── 表达层（我们的差异化）
             3D 可钻取图谱 + 3D 课件 + 对话式提问
```

医助通的「异常指标 → 病因链 → P0–P4 分级」和这里的「错题 → 前置链 → 卡点」是**同一个算法的两个实例**。引擎层写一次，两个赛道共用。

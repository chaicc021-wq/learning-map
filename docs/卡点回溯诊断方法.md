# 卡点回溯诊断方法

> 一句话：**孩子做错题，错的是"现在这一步"；卡点在"更早的那一步"。这套方法用依赖图把卡点定位出来，并且给出该往回补哪一格。**

## 为什么这样做

传统测评告诉你"百以内加法不行"。这句话没法执行——因为"百以内加法不行"可能来自五种完全不同的原因：

| 表现一样 | 真实卡点 | 正确处方 |
|---|---|---|
| 47+8 算错 | 数位含义没建立（不知道 47 里的 4 是 40） | 回头补小棒捆演示数位 |
| 47+8 算错 | 凑十法不熟（8 差几凑 10 要想半天） | 补 10 的互补数自动化 |
| 47+8 算错 | 10 以内口算不自动化（还在掰手指） | 补口算熟练度 |
| 47+8 算错 | 数位和凑十都会，只是没练过进位 | 直接练这个点 |
| 47+8 算错 | 题意读不懂 | 补读题，不是补计算 |

**前四种是能力缺口，最后一种是练习缺口。处方完全相反。** 传统测评分不开这两种，所以家长只能"多做题"，而多做题对能力缺口无效——这就是"补了很多还是不会"的原因。

## 引擎怎么工作

```
目标知识点（孩子出错的那格）
        ↑ traceUp：沿 hard 前置回溯，最多 4 层
地基优先排序（深度大 = 更接近地基）
        ↓ 逐格提问
每格：assessmentPrompt → 本地模型 → 中文现场诊断题 + 追问
        ↓ 家长转述孩子真实表现（原话/动作）
本地模型判定三档：mastered / partial / not_mastered
        ↓
问到第一个 not_mastered 就停（上面必然连带失败，不必再问）
        ↓
【卡点】+【为什么】+【为什么表现为目标出错】+【处方】+【补完解锁】
```

三个设计要点：

1. **地基优先问，问到失败即停。** 最少问题数定位根因。实测 14 层前置链，通常 3–5 问就断。
2. **三档判定，不是对错二分。** `partial`（蒙对/只会在熟悉场景做/换个说法就不会）是最常见也最有信息量的一档——它说明概念建立了但没自动化，处方是变式练习而不是重讲。
3. **裁判不许放水。** 家长转述证据不足时判 `partial` 而不是 `mastered`（实测：家长只说"写得很标准"、没描述笔顺 → 判 partial 并要求现场演示）。

## 中文化层（不是翻译）

上游是欧美课程体系，直接给中国家长用会出错。引擎在同一次模型调用里顺手产出四样东西：

| 字段 | 作用 |
|---|---|
| `name` / `meaning` | 用中国课标常用词（"十几数的组成""两位数数位含义""凑十法""十进制打包"），不直译 |
| `fit` | 判断对中国小学生 **适用 / 需调整 / 不适用** |
| `fit_note` | 需调整时说明怎么调 |
| `why` | 中文说明它为什么是后面那些知识的地基 |

实测 `fit` 判断质量（自动识别，非人工指定）：

- `Coin Values` → **需调整**：原知识点基于英国货币 p/£，中国孩子应替换为元/角/分
- `Number Words to Twenty` → **需调整**：中国教材不教英文单词拼写，重点在"十几"的读法与写法
- `Representing Numbers` → **需调整**：中国教材用小棒（捆成10根）和计数器，不用 base-ten blocks
- `Writing digits 0-9` → 判"适用"，但诊断题被改写成用筷子摆字形（原场景是英文 handwriting）

`不适用` 的点在 plan/session 里自动跳过并说明原因。

## 命令

```bash
# 1. 摸底：还不知道卡在哪，先出地基题单（可打印版自动存 sessions/）
python scripts/diagnose.py screen --subject Mathematics --age 7 --n 12

# 2. 看某格的前置链长什么样、每格怎么问
python scripts/diagnose.py plan --topic mt_glPPG-kTQY --depth 4

# 3. 现场诊断（一问一答，问到失败即停，自动出报告并存档）
python scripts/diagnose.py session --topic mt_glPPG-kTQY

# 4. 单独问一道题 / 单独判一次
python scripts/diagnose.py ask   --topic mt_xmmgAzxe5j
python scripts/diagnose.py judge --topic mt_xmmgAzxe5j --answer "他把14块排成一排14个，不知道怎么打包成10"

# 5. 重看历史会话报告
python scripts/diagnose.py report --session sessions/20261019_2245_mt_glPPG-kTQY.json
```

环境变量：`DIAG_CHILD`（孩子名字，默认"予淳"）、`DIAG_API`（模型端点，默认 `http://127.0.0.1:8088/v1/chat/completions`）。

## 成本与性能（实测）

| 环节 | 实测 |
|---|---|
| 生成一道中文诊断题 | 约 2 秒（Strata 8088，本地） |
| 判定一次孩子表现 | 约 2 秒 |
| 14 层前置链全量预热 | 75 秒（3 路并发） |
| 摸底单 12 题 | 42 秒 |
| 缓存命中后重复调用 | 0 秒（`scripts/_qcache.json`） |

**关键结论：诊断不需要题库。** 上游给的 `assessmentPrompt` 是"给老师的提问建议"，本地模型把它变成现场可操作的中文题——这条路绕开了头部厂商的题库壁垒。

## 已验证 / 未验证（诚实边界）

**已验证（有实测输出）**
- 前置回溯正确性：`Addition within 100` 回溯出凑十法、十进制打包、两位数数位含义——与中国课标结构吻合
- 中文题质量：7 岁可听懂、场景贴近中国课堂、无术语
- 三档判定准确性：三种典型表现（做对且能说理由 / 做对但说不出 / 完全做错）判定正确
- 裁判不放水：转述证据不足判 partial
- 问到失败即停、报告两条分支（能力缺口 vs 练习缺口）
- 根因判定：同深度优先选"完全不会"而非"半会"（修过一个真 bug）

**未验证（必须做）**
- **对真实孩子的判定准确率。** 目前所有判定都是模拟转述。真实风险：孩子"会做但不肯说"、"心情不好乱答"、"家长转述失真"——这三种情况模型能不能扛住，只有真人跑过才知道。
- 上游前置链对中国教材的**完备性**：Marble 的数学只有 503 格，中国小学数学知识点量级 1,500–3,000，一定有中国教了、Marble 没有的环节（例如"破十法"退位减法）。
- 上游前置链的**正确性**：个别边可能是模型生成的产物，需要人工抽查。
